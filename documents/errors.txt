RESOLVED — 2026-06-09

Error (original):
  org.springframework.beans.factory.BeanCreationException: Error creating bean with name 'persistenceExceptionResolver'
  defined in class path resource [org/axonframework/springboot/autoconfig/JpaAutoConfiguration.class]:
  Failed to instantiate [org.axonframework.common.jdbc.PersistenceExceptionResolver]:
  Factory method 'persistenceExceptionResolver' threw exception with message: The connection attempt failed.

  HHH100046: Could not obtain connection to query JDBC database metadata
  org.hibernate.exception.JDBCConnectionException: Unable to obtain isolated JDBC connection [The connection attempt failed.]

Root Cause:
  Port conflict between kafka-connect (Debezium, port 8083:8083) and order-service (Spring Boot, port 8083:8083).
  Docker created the fs-order container but FAILED to attach it to the flashsale-net network
  because host port 8083 was already bound by fs-kafka-connect.
  Without network attachment, fs-order could not resolve hostname "postgres", causing
  UnknownHostException → PSQLException → BeanCreationException.

Fix Applied:
  1. Added PORT_KAFKA_CONNECT=18083 to .env and .env.example
  2. Changed kafka-connect port mapping from "8083:8083" to "${PORT_KAFKA_CONNECT:-18083}:8083"
     in both docker-compose.yml and docker-compose-infrastructure.yml
  3. Updated Makefile connect-register and connect-status targets to use port 18083
  4. Restarted kafka-connect and order-service containers

Result:
  - fs-kafka-connect now binds to host port 18083 (Debezium REST API)
  - fs-order binds to host port 8083 (Spring Boot / order-service API)
  - fs-order is properly attached to flashsale-net and can resolve "postgres"
  - All containers healthy, order-service started successfully in ~23s
