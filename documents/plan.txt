## Phạm vi

3 kênh thanh toán chính, mỗi UC verify đồng thời ở 3 nơi: **API/DB**, **JUnit E2E**, **Stripe Dashboard**.

- **Channel 1 — Checkout → PaymentIntent → Webhook:** UC-11.1 / 11.2 / 11.3 / 11.7 / 11.8.
- **Channel 2 — Refund:** UC-11.4 (partial), UC-11.9 (charge.refunded).
- **Channel 3 — Connect (Onboarding + Transfer + Payout):** UC-11.6.* + UC-11.10 + payout scheduler.
- **Channel 4 — Bảo mật webhook:** UC-11.11.

Out of scope: identity/catalog/notification flows (đã có UC riêng), chỉ chạm khi cần seed dữ liệu.

## Phase B — Bổ sung E2E suite (JUnit) cho 8 UC chưa cover

Thêm test methods vào lớp tương ứng. Tái sử dụng `E2eSupport`, `StripeWebhookForge`. Test framework: JUnit 5 + Awaitility, dùng pattern poll như các test hiện có.

### B1. `A16StripeOnboardingE2eTest` — thêm 3 method
File: [A16StripeOnboardingE2eTest.java](backend/e2e-tests/src/test/java/com/flashsale/e2e/A16StripeOnboardingE2eTest.java)
- `buyerStartOnboardingReturns403()` (UC-11.6.2) — login BUYER, POST `/stripe/onboarding/start` → assert 403.

- `parallelStartProducesDistinctAccountIds()` (UC-11.6.8) — register 2 seller mới, parallel POST `/start` qua `CompletableFuture`, assert 2 distinct `stripeAccountId`.

### B2. `A15WebhookHandlersE2eTest` — thêm 2 method

### B3. `A14SellerTransferE2eTest` — thêm 2 method

## Phase C — UC-11.6.9 Real Stripe TEST account qua Dashboard (manual)

Mục đích: validate non-mock branch — `StripeOnboardingService` gọi Stripe API thật, không fallback `acct_mock_*`. Đã có `STRIPE_API_KEY=sk_test_...` trong `.env` (user xác nhận).

**Bước 1 — Kiểm `.env`:** xác nhận `STRIPE_API_KEY` bắt đầu bằng `sk_test_` (không phải `sk_test_FAKE` placeholder). Nếu cần restart: `docker compose -f docker-compose.yml -f docker-compose.dev.yml restart payment-service`.

**Bước 2 — Register + onboarding:**
- Register seller mới `realseller$(date +%s)` qua `POST /api/v1/auth/register/seller`.
- POST `/api/v1/stripe/onboarding/start` → response phải có `stripeAccountId` KHÔNG bắt đầu bằng `acct_mock_`, và `onboardingUrl` trỏ tới `connect.stripe.com/setup/...`.

**Bước 3 — Hoàn tất KYC trên onboarding URL (qua Chrome MCP, hiển thị ở màn hình Arzopa):**
- Dùng `mcp__claude-in-chrome__navigate` mở `onboardingUrl`. Stripe test mode auto-fill được với data fake (test SSN `000-00-0000`, routing `110000000`, account `000123456789`, business URL `https://example.com`).
- Sau khi submit, Stripe gửi `account.updated` webhook thật qua `stripe-listener` container → `payment-service` cập nhật DB.

**Bước 4 — Đối chiếu Dashboard admin:**
- Mở https://dashboard.stripe.com/acct_1T9nfQCma465d2uk/test/connect/accounts qua Chrome MCP.
- Confirm account `stripeAccountId` từ bước 2 hiện trong danh sách Connected accounts với badge "Complete".
- GET `/api/v1/stripe/onboarding/status` → assert `chargesEnabled=true`, `payoutsEnabled=true`, `onboardingStatus=COMPLETE`.

**Bước 5 — End-to-end real PaymentIntent:**
- Buyer `minhhoa` mua product của seller mới → checkout → `awaitTransactionStatus PENDING`.
- Lấy `clientSecret` từ PaymentIntent (qua DB trực tiếp hoặc `GET /payments/parent-order/{id}` nếu DTO có expose), confirm bằng Stripe test card `4242 4242 4242 4242` qua Stripe Hosted Page (mở URL trong Chrome MCP).
- `stripe-listener` forward `payment_intent.succeeded` thật (không forge HMAC) → assert sub-orders PAID.
- Verify trên Dashboard: PaymentIntent succeeded, Transfer to seller account xuất hiện trong tab Transfers của Connect account đó.

**Pass criteria:** stripeAccountId không có prefix `acct_mock_`, KYC complete trên Dashboard, PaymentIntent thật succeeded với transfer xuất hiện ở seller Connect account.

## Phase D — Smoke "Stripe CLI forward thật" (live integration, không forge)

Khác Phase C: ở đây không qua Stripe Hosted Page, chỉ verify rằng container `stripe-listener` đang forward đúng và `payment-service` chấp nhận signature do Stripe CLI ký (≠ signature do `StripeWebhookForge` ký).

```bash
docker logs stripe-listener --tail 20
# Phải thấy: "Ready! You are using Stripe API Version [2024-06-20]"
# Webhook signing secret in env STRIPE_WEBHOOK_SECRET phải khớp với log dòng "Your webhook signing secret is whsec_..."

# Trigger event thủ công từ host (Stripe CLI cài local hoặc exec vào container):
docker exec -it stripe-listener stripe trigger payment_intent.succeeded
# → stripe-listener forward tới fs-payment:8082, payment-service log "Received Stripe webhook event"
```

**Pass criteria:** `payment-service` log "Received Stripe webhook event" + 200 response, không có "Invalid signature" exception.
